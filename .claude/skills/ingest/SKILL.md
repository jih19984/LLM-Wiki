# /ingest — 지식 소화 및 승격

원본 캡처를 분석해서 진짜 지식으로 정제하는 커맨드. **요약만 하고 끝내지 않는다** — 엔티티를 추출하고, 기존 지식과 연결하고, 신뢰도를 매겨서 semantic으로 승격시키는 것까지가 완료 기준이다.

이 볼트에서의 매핑: `raw/` = `01-working-memory/`, `wiki/` = `03-semantic/`. 자세한 폴더 역할은 `/CLAUDE.md` 참고.

## 대상

`01-working-memory/` 안의 문서 중 frontmatter에 `ingested: true`가 없는 것.
- frontmatter가 아예 없는 파일도 미처리로 간주한다.
- `_index.md`는 안내 문서이므로 대상에서 제외한다.

## 절차

1. **스캔**: `01-working-memory/` 하위 파일을 훑어 `ingested: true`가 아닌 파일을 찾는다.
2. **분석 (요약 금지)**: 각 문서에서 다음을 추출한다.
   - 핵심 인물 (Person)
   - 프로젝트/이니셔티브 (Project)
   - 기술 개념 (Concept) — CS 개념, 라이브러리, 패턴 등
   - 각 엔티티에 대해 "이 문서가 뭐라고 말하는가"를 한두 문장으로 정리
3. **기존 지식과 연결**: `03-semantic/`을 탐색(파일명·제목·tags 기준)해 겹치는 엔티티가 있는지 확인한다.
   - 이미 있는 개념/자산 → 새 노트를 만들지 말고 **기존 노트를 업데이트** (내용 보강, `sources`에 이번 자료 추가, `related` 갱신, `updated` 날짜 갱신)
   - 새로운 개념/자산 → `_templates/concept.md` 또는 `_templates/code-asset.md`를 복사해 새 노트 생성
   - 연결이 발견되면 반드시 `related`에 명시한다.
4. **외부 검증 (팩트체크)**: 문서 안의 사실관계 주장 중 객관적으로 맞고 틀림을 가릴 수 있는 것은 WebSearch/WebFetch로 실제 검증한다.
   - 검증 대상: 기술 스펙, 동작 방식, 버전 정보 등 확인 가능한 사실 (예: "Redis TTL 기본값은 -1이다", "X 라이브러리는 Y를 지원한다")
   - 검증 제외: 개인 의견, 이 프로젝트 고유의 맥락(예: "우리 팀은 이렇게 쓰기로 했다"), 이미 위키에서 교차검증된 내용 — 문장 하나하나 다 검색하지 않는다
   - 공식 문서·1차 출처를 우선하고, 찾은 근거는 `sources`에 URL로 남긴다
   - 검색 결과가 원문과 다르면 노트를 임의로 고치지 않는다 — 차이를 사용자에게 보고하고 판단을 구한다 (원문이 오래된 버전 정보일 수도, 검색 결과가 특정 조건에만 해당할 수도 있다)
5. **신뢰도 부여**: 아래 기준으로 `confidence`(0.0~1.0)를 판단해 frontmatter에 기록한다.
   - 웹 검증에서 공식 문서 등 신뢰할 수 있는 출처로 확인됨 → 0.8~0.95
   - 이미 위키에 있는 다른 노트와 교차 검증됨(같은 내용을 다른 출처에서도 확인) → +0.2 가산
   - 출처가 불분명하거나 개인 추측/메모 수준, 검증 불가 → 0.4 이하로 낮게 시작
   - 웹 검증 결과와 모순됨 → 0.3 이하로 낮추고 모순 내용을 본문에 명시, 사용자에게 보고
   - 처음 작성이면 기본 0.5에서 위 기준으로 가감
   - 왜 이 점수인지, 무엇으로 검증했는지 `sources` 또는 본문 "참고"란에 한 줄 근거를 남긴다
6. **MOC 연결**: 새로 만들거나 갱신한 노트를 관련 MOC(`MOC-CS` 또는 `MOC-코드자산`)에 링크한다.
7. **완료 표시**: 처리한 원본 문서의 frontmatter에 `ingested: true`를 추가/갱신한다 (중복 처리 방지). 원본 본문은 삭제하지 않고 그대로 둔다.

## 완료 후 보고

- 새로 만든 semantic 노트 목록 (경로)
- 업데이트된 기존 노트와 무엇이 왜 바뀌었는지
- 웹 검증을 거친 주장과 그 출처, 원문과 다르게 나온 게 있었다면 그 차이
- 부여한 confidence와 근거
- `ingested` 처리된 원본 파일 목록
- 판단이 애매한 것(신뢰도 낮은 자료, 기존 노트/검색 결과와 상충되는 내용 발견 등)은 임의로 덮어쓰지 말고 먼저 사용자에게 확인한다
